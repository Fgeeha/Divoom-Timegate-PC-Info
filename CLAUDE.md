## 1. Что это за проект

Кроссплатформенное приложение, которое:

1. Собирает телеметрию о компьютере (CPU/GPU load и температура, RAM, сеть, и т.д.).
2. Поднимает локальный HTTP-сервер, отдающий эти данные.
3. Управляет пиксельными часами **Divoom Times Gate** (ESP32, 5 дисплеев 128×128) по локальной сети, выводя телеметрию на дисплеи.

Часы работают полностью в локальной сети: облако Divoom не нужно для управления (нужно только при первичной активации часов). Подробности протокола — раздел 4.

Целевые платформы: **Linux (Ubuntu LTS + базовые пакеты)** и **Windows 11**.

## 4. Протокол Divoom Times Gate (сверено со статьёй и docin.divoom-gz.com/web/#/5)

### 4.1 Базовые факты
- Все команды — JSON, `POST` на `http://<DevicePrivateIP>/post`.
- Успех: в ответе JSON `error_code == 0`. Любая ошибка формата → строка `"Request data illegal json"` (причина не детализируется — отлаживай payload вручную).
- Имена параметров чувствительны и содержат опечатки в самой прошивке — **писать ровно как в доке**. В частности фон называется `BackgroudGif` (опечатка намеренная, так ждёт устройство).
- Дисплеи индексируются `LcdIndex` 0–4.
- GIF: 16×16 / 32×32 / 64×64 / 128×128, грузятся с HTTP-сервера (наш `server.py`).

### 4.2 Дискавери (получение IP часов)
Запрос к облаку возвращает все устройства Divoom, вышедшие в интернет с того же внешнего IP:

```
POST https://app.divoom-gz.com/Device/ReturnSameLANDevice
```
Ответ содержит `DeviceList[].DevicePrivateIP` и `DeviceMac`. Используем как **опциональный** способ авто-обнаружения. Не полагаться на него как на единственный — см. раздел 5.

### 4.3 Вывод фона + текста: `Draw/SendHttpItemList`
Ключевой метод. За один запрос: фон + текстовые поля.

```json
{
  "Command": "Draw/SendHttpItemList",
  "LcdIndex": 0,
  "NewFlag": 1,
  "BackgroudGif": "http://<our_ip>:<port>/images/bg.gif",
  "ItemList": [{
    "TextId": 1,
    "type": 23,
    "x": 0, "y": 110, "dir": 0,
    "font": 4,
    "TextWidth": 128, "Textheight": 16,
    "TextString": "http://<our_ip>:<port>/text/0",
    "speed": 100,
    "color": "#FFFFFF",
    "update_time": 1
  }]
}
```

Важные нюансы (из статьи, проверено эмпирически):
- `NewFlag=1` обновляет фон; `NewFlag=0` — нет.
- **Не используй статический текст (`type:22`) для часто меняющихся данных** — любое обновление текста вызывает экран «Loading» (песочные часы).
- Для динамики используй **«интернет-текст» `type:23`** (`DIVOOM_DISP_CUSTOM_DIAL_SUPPORT_NET_TEXT_MESSAGE`): в `TextString` кладётся URL, часы сами опрашивают его раз в `update_time` секунд и берут поле `DispData` из JSON-ответа. Так текст меняется без «Loading».
- Поэтому пайплайн: **один раз** разложить поля через `SendHttpItemList`, дальше менять только то, что отдаёт наш веб-сервер по `/text/{id}` (`{"DispData": "..."}`).

### 4.4 Шрифты (`font`)
Списка шрифтов от API получить нельзя (заглушка). Найдено перебором 1–44:
- Алфавитные (латиница/кириллица/иероглифы): **2, 4, 32**.
- Числовые со спецсимволами погоды: 18, 20, 22, 26, 28, 42.
- Числовые: 24, 30, 36, 44.
- Размер шрифта менять нельзя.

### 4.5 Чего НЕЛЬЗЯ
- Версию прошивки не узнать.
- Шкал прогресса нет — только картинка + текст.
- Выравнивание текста по центру/правому краю не работает (несмотря на доку).
- Слишком частые/многочисленные запросы → «зависает» подсветка. **Не спамить**: разумный минимум обновлений, `update_time` ≥ 1 c, не дёргать `SendHttpItemList` без необходимости.

## 5. Передача данных и IP часов (требование задачи)

IP часов — изменяемая конфигурация, не хардкод. Разрешение адреса по приоритету:

1. CLI-флаг `--device-ip` / переменная окружения `DIVOOM_DEVICE_IP`.
2. Значение из конфиг-файла (`config.toml`, ключ `[device].ip`).
3. Авто-дискавери через `ReturnSameLANDevice` (раздел 4.2) — если включён `[device].autodiscover = true`.
4. Если ничего не найдено — внятная ошибка с подсказкой, как задать IP.

Наш веб-сервер слушает на адресе, который тоже конфигурируется (`[server].listen_host`, `[server].listen_port`), потому что **часы должны достучаться до нас по сети** — `127.0.0.1` не подойдёт, нужен LAN-адрес машины. По умолчанию пытаемся определить LAN-IP автоматически, но позволяем переопределить.

Поток данных:
```
collectors → внутреннее состояние → FastAPI /text/{id} (DispData)
                                  ↘ /images/*.gif (фоны)
часы periodically GET /text/{id}  ← (через update_time)
divoom.client POST /post (разовая раскладка полей)
```

Конфиг — единственное место с адресами. Пример держим в `config.example.toml` без реальных значений; реальный `config.toml`/`.env` — в `.gitignore`.

## 6. CI/CD (требование задачи)

GitHub Actions, файл `.github/workflows/build.yml`. Матрица:

- **Linux**: `ubuntu-latest` (Ubuntu LTS). Ставить системные зависимости через `apt` (например `lm-sensors` для температур). Python из `actions/setup-python`.
- **Windows 11**: `windows-latest`.

Каждый job:
1. checkout;
2. setup Python (фиксированная минорная версия, напр. 3.12);
3. установка зависимостей (`pip install .[dev]`);
4. lint (`ruff`) + тесты (`pytest`);
5. сборка автономного бинаря (`pyinstaller`) под платформу;
6. публикация артефактов (`actions/upload-artifact`): `divoom-pc-monitor-linux`, `divoom-pc-monitor-windows.exe`.

Правила для CI:
- Никаких секретов в workflow. Если когда-то понадобится публикация — только через GitHub Secrets, и упомянуть в README.
- Любые git-операции в CI — анонимны (`anon <anon@localhost>`), см. 2.1.
- Кэшировать pip для скорости.
- Workflow обязан проходить и на push, и на pull_request.
- При изменении состава артефактов/платформ — обновить README (раздел «Скачать сборки»).

## 7. Технологический стек (по умолчанию)

- Язык: **Python 3.12+** (кроссплатформенно, есть `psutil`, `requests`, `FastAPI` — всё из статьи).
- Телеметрия: `psutil`; Linux-температуры через `psutil.sensors_temperatures()` / sysfs; Windows GPU/темпы — опционально через LibreHardwareMonitor (документировать как опциональную зависимость, не требовать жёстко).
- Веб-сервер: `FastAPI` + `uvicorn`.
- HTTP-клиент к часам: `requests`.
- Сборка: `pyinstaller`.
- Линт/тест: `ruff`, `pytest`.

Если предлагаешь сменить стек — сначала обоснуй и спроси.
